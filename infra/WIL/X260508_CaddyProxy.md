# X-2. Caddy Proxy를 통한 VM HTTPS 환경 제공

## 실행   
GSMSV를 운영하던 중 지속적으로 HTTPS 환경 제공에 대한 요청이 들어왔다, 처음엔 그냥 필요한 사람만 Cloudflare Flexible로 하면 되는거 아닌가... 싶었지만 서버에서 기본적으로 제공해준다면 나쁘지 않을 것 같아서 리버스 프록시로 구현해보기로 했다.  
  
### 1. Caddy 선택  
사실 처음에는 Caddy가 어떤 서비스인지도 몰랐다, 내가 아는 리버스 프록시 구현은 Nginx로 하는것 밖에 없었는데 이런 환경에서 Nginx를 쓴다면 파일 내용도 계속 바뀌고 재시작도 여러번 하고 URL도 보기 좋지 않을 것 같았다  
 이런 저런 서비스를 알아보다가 Caddy와 Traefik을 알게 됐는데 Traefik은 컨테이너 환경에 최적화 되어있기도 하고 Caddy는 Admin API(:2019)를 통해 재시작 없이도 라우트를 수정할 수 있다 들어서 Caddy를 사용하기로 했다  

### 2. NS 위임 및 와일드카드 인증서  
HTTPS 서비스를 쓸 때 gsmsv.site:nnnnn 같이 뒤에 포트번호로 붙히면 가독성도 그렇고 HTTPS인데 왜 443이 아니지? 라는 의문점을 가질수도 있을거 같아 \*.https.gsmsv.site 서브도메인을 만들어 {service}.https.gsmsv.site 와 같은 URL을 사용할 수 있게 만들었고 DNS-01 Challenge를 쓰기 위한 설정도 해두었다  

### 3. Caddy VM 구축  
Caddy를 라우터에서 돌리기에는 자원 사용량도 걱정되고 Caddy 서버 관리를 용이하게 하기 위해 Caddy서비스 전용 VM을 하나 만들기로 했다.  
 Claude의 도움을 받아 Caddy 설정을 끝마치고 라우터에서 80/443으로 오는 트래픽을 Caddy Server로 포트포워딩 해두니 잘 작동했다, 인증서 관리도 자동화 해두었으니 크게 신경쓰지 않더라도 잘 돌아갈 것이다  
  
### (예정) 4. API를 통한 자동화
나는 코드를 잘 못짜다보니 Claude와 Codex로 코드 구현을 하고 나는 비지니스 로직 설계와 환경변수등만 좀 만질 것 같다...! 그러나 요즘 Flooding 개발도 하고 있고 GSMSV도 팀원들을 구하고 많은 것들이 바뀌고 있어서 이 일정은 미뤄질 수도 있겠다.  

## 결과     
현재는 수동으로 Caddyfile을 수정하고 재시작해야 적용되지만 그래도 신청자에 한해서 적용되기때문에 자동화는 조금 늦어도 될것같다..ㅎ; 잘 작동하는걸로 만족중
